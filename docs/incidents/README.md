# Incident Evidence — Historical Only

Files in this directory are retained because they contain unique incident/forensic evidence. They are **HISTORICAL**, not current product, architecture, task or runtime authority.

Before using one of these files:

1. Verify the current source/runtime identity independently; historical evidence does not establish current task authorization or host permissions.
2. Treat branch names, PR states, source heads, runtime PIDs, device state and proposed fixes inside an incident file as facts about that captured window only.
3. Do not revive Persistent, dual-receiver, Receiver B, local-microphone voice-button or other retired semantics because an older incident mentions them.
4. Do not perform historical app/driver/CoreAudio/TCC remediation merely because an incident describes it; those are distinct runtime side effects requiring current authority.
5. Use current source/tests and `docs/DOMAIN_MAP.md` to locate the present implementation before drawing a causal conclusion.

Incident evidence can establish what was observed at the time. It does not automatically establish current behavior or root cause.
